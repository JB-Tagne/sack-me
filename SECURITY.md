# Security Policy · Politique de sécurité

[Français](#français) · [English](#english)

## Français

### Versions supportées

La branche `main` reçoit les correctifs de sécurité.

### Signaler une vulnérabilité

N’ouvre **pas** d’issue publique pour un secret exposé ou une faille exploitable.

Envoie un message privé au mainteneur du dépôt (onglet Security → Advisories sur GitHub si disponible), avec :

- description de l’impact
- étapes de reproduction
- version / commit concerné

Ne joins jamais de mots de passe ou clés API réelles dans les tickets.

Les identifiants locaux de démo (`sackme` / `sackme`) ne doivent **pas** être utilisés en production.

---

## English

### Supported versions

The `main` branch receives security fixes.

### Reporting a vulnerability

Do **not** open a public issue for an exposed secret or exploitable flaw.

Contact the repository maintainer privately (GitHub Security → Advisories when available), including:

- impact description
- reproduction steps
- affected version / commit

Never attach real passwords or API keys to tickets.

Local demo credentials (`sackme` / `sackme`) must **not** be used in production.
